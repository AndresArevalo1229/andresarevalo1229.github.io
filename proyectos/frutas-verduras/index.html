Resumen

Desarrollé el frontend de una aplicación para consultar inventario, organizar viajes y preparar ventas de frutas y verduras. Mi trabajo incluyó formularios, filtros, paginación y estados de interfaz, además de la adaptación de las respuestas de la API a modelos y componentes TypeScript.

El caso se centra en la preparación de ventas por cajas o kilogramos: un flujo que relaciona producto, proveedor, viaje y existencias. El backend fue desarrollado por otros integrantes; mi contribución corresponde al cliente web.

El problema

Una venta necesita conservar el contexto del producto y del viaje del que procede, y representar cantidades con unidades distintas. La interfaz debe mostrar la disponibilidad, validar la captura y comunicar qué información falta o está pendiente de cargar antes de enviar la operación.

Mi aportación

  • Desarrollé vistas de inventario, viajes y ventas con componentes y formularios React/TypeScript.
  • Integré las APIs REST del equipo para consultar productos, proveedores, viajes y existencias, y transformar sus respuestas para la interfaz.
  • Implementé el flujo de selección y captura de cantidades en cajas o kilogramos, con validaciones y nueva consulta de disponibilidad antes del envío.
  • Incorporé filtros, paginación y estados de carga/error en los recorridos de consulta; atendí errores reportados por el equipo durante su validación.

Arquitectura del recorrido

La interfaz React organiza páginas y componentes y utiliza servicios HTTP para consultar las APIs del equipo. React Router gestiona la navegación y Context API participa en el estado compartido. TypeScript permite expresar los datos que la interfaz recibe y utiliza.

Tecnologías: React, TypeScript, JavaScript, Vite, React Router, Context API, Fetch y CSS.

Reto técnico: preparar una venta con contexto y unidades

El recorrido debe mantener relacionados el producto, el proveedor, el viaje y las cantidades elegidas. La captura cambia según la información disponible y admite cajas y kilogramos. La solución en el frontend combina consultas REST, estado de selección, campos tipados y validación de cantidades; antes de enviar se consulta de nuevo la disponibilidad.

Esa comprobación del cliente ayuda a trabajar con información reciente, pero la consistencia entre operaciones simultáneas pertenece al servidor. No presento este caso como una implementación personal de inventario transaccional en el backend.
